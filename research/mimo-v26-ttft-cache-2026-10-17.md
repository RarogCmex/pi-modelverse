# MiMo v2.6: prompt cache попадает, TTFT от хита не падает (2026-10-17)

Повод: на `mimo-v2.6-*` наблюдается большой TTFT, и выглядело так, будто
`X-Session-ID` (сродство сессии к инференс-инстансу, см. README «Prompt
caching») не работает. Живая проба на `https://api.modelverse.cn/v1`,
`mimo-v2.6-flash`, широкий ключ (KEY1; листинг того дня — 273 id, mimo-v2.6
есть и у промо-ключа). Поверхность — `/responses`, та, которой плагин
маршрутизирует mimo. Промпт — стабильный филлер «The quick brown fox…»,
`store: false`, стрим, если не сказано иное.

## 1. Кэш на шлюзе работает

`usage.input_tokens_details.cached_tokens` приходит и в стриме, и в
нестриминговом ответе. Хиты квантуются блоками по 64 токена (3968, 4416,
17728), хвост короче блока остаётся miss. Повтор того же префикса:

| Проба | cached / input | что это |
| --- | --- | --- |
| первый запрос сессии, ~4 030 токенов | **0 / 4030** | холодный miss |
| 2-й и 3-й, тот же `X-Session-ID` | **3968 / 4030** | 98,5% |
| повтор ~17 787 токенов, тот же session | **17728 / 17787** | 99,7% |
| ~16k сразу после ~4k из того же филлера | **4416 / 17787** | частичный хит общего префикса, не весь промпт |

pi-ai это поле читает: в бандле pi 1.2.x разбор responses кладёт
`input_tokens_details.cached_tokens` в `usage.cacheRead`, так что хит виден в
статистике сессии и тарифицируется по `cacheRead` каталога (у mimo ¥0,02
против ¥1 за вход).

## 2. Хит не снижает TTFT пропорционально префиллу

`reasoning.effort: "none"` (в usage `reasoning_tokens: 0`), стрим. TTFT — время
до первого байта тела, «text» — до первой `response.output_text.delta`.

| Запрос | TTFT | до текста | cached / input |
| --- | --- | --- | --- |
| холодный, ~4 030 | 2,1 с | 4,3 с | 0 / 4030 |
| повтор, тот же session | 3,3 с | 4,6 с | 3968 / 4030 |
| третий повтор | 1,3 с | 3,4 с | 3968 / 4030 |

Нестрим, тот же `effort: none` (время — полный round-trip, выход 8 токенов):

| Запрос | время | cached / input |
| --- | --- | --- |
| холодный, 237 токенов | 1,6 с | 0 / 237 |
| холодный, ~4 457 | 5,1 с | 0 / 4457 |
| ~17 787, частичный хит | 7,0 с | 4416 / 17787 |
| повтор ~17 787, 99,7% хит | **10,3 / 3,8 / 5,0 с** | 17728 / 17787 |
| 4 параллельных идентичных ~4,5k, разные session | 2,2–2,9 с (wall 2,9 с) | 4416 / 4457 у всех |

Полный хит на 16k не быстрее холодного запроса на 237 токенов. Четыре
параллельных запроса уложились в то же окно, что и одиночный, — это не очередь
на шлюзе. Дефолтный effort (без `none`) добавляет сверху генерацию reasoning:
на ~4k тот же префикс дал TTFT 2,7 с и 6,6 с до текста при `reasoning_tokens: 10`.

## 3. `X-Session-ID` для mimo не является узким местом

Заголовок плагин отправляет: `Agent.sessionId` доходит до `options.sessionId`
(`buildBaseOptions` в pi-ai), `withSessionAffinity` ставит `x-session-id`, если
его ещё нет. pi сам для openai-responses шлёт `x-session-id` только при
`sessionAffinityFormat: "openrouter"`, а у записей modelverse на `/responses`
этот формат не задан — заголовок добавляет обёртка, не адаптер.

Но идентичный префикс получил 3968/4032 и **без** заголовка. Это не чистый
A/B (запросы без заголовка шли сразу после прогретых тем же префиксом), зато
показывает, что шлюз роутит повтор по хэшу префикса и без session id. Доки
UCloud (`astraflow.ucloud.cn/docs/modelverse/best_practice/improve-prompt-cache`)
описывают `X-Session-ID` как best-effort сродство, не привязку к инстансу:
перепланирование возможно при нагрузке, недоступности инстанса и по TTL
аффинити. Заголовок оставлен как страховка; для mimo он не объясняет TTFT.

## 4. То же самое у upstream Xiaomi

Официальный API (`mimo.mi.com/docs/en-US/api/chat/openai-api`) отдаёт тот же
`prompt_tokens_details.cached_tokens` и тарифицирует cache hit отдельно
(`mimo-v2.6-flash`: ¥0,02 / ¥1 / ¥2). На `api.xiaomimimo.com` пользователи
прямо меряют, что hit rate и TTFT расходятся: при падении хита с ~90% до ~40%
TTFT вырос с ~4 с до 6–7 с, то есть даже «здоровые» 90% оставляют TTFT в
секундах (XiaomiMiMo/MiMo-V2-Flash#26, 2026-08). Modelverse здесь ничего не
теряет относительно upstream.

## Вывод

Менять плагин не нужно. Кэш попадает, учитывается pi и стоит в 50 раз дешевле
входа. Секунды TTFT — латентность инференса mimo на этом шлюзе, а не
промах кэша и не потерянный `X-Session-ID`. Единственный рычаг на стороне
запроса — `reasoning.effort: "none"`, когда рассуждение не нужно: срезает
хвост генерации, но не задержку до первого байта.
